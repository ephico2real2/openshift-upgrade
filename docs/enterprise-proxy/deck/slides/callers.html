Four Red Hat host groups carry the whole update. The admin's only action is choosing the target version; the Cluster Version Operator then drives the rest. Our proxy allowlist holds the full list from Red Hat's firewall page. The CVO also tries the other documented signature source, storage.googleapis.com; the proxy denies it, and Red Hat says the CVO needs only a single functioning source, so expect that deny in the proxy logs. OLM schedules the catalog and operator pods; CRI-O on the node does the pull.
