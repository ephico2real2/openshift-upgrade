What the threat model shows

1

The platform starts every update

The Cluster Version Operator, CRI-O and OLM make the requests; an admin only picks the target

2

Named Red Hat hosts, TCP 443, our proxy

Four host groups, nothing else; the firewall lets only the proxy out

3

Application pods have no way out

The platform gives them no proxy settings, and the firewall stops them: the one condition for security

4

Only allowed registries

Red Hat's and ours: checked on every pull, and refused at admission

3 / 12

Four claims, each backed by a control in the following slides. Controls C1 to C7 come from Red Hat's OpenShift documentation; C8, the admission policy, is ours. Point 3 is the one condition of the change with security: applications cannot use the proxy by default. A team that sets a proxy in its own deployment does so by choice, under existing policy; that is not something the platform does.
