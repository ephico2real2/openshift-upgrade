Step 2 · the platform owner's decision

Clusters reach Red Hat through the proxy

  • Each cluster's Proxy setting sends platform traffic to the enterprise proxy, which allows only Red Hat's documented hosts
  • Application pods are blocked from the proxy; an image allowlist stops arbitrary pulls
  • No mirror, no sync, no local Update Service, no two-headed DNS. Proxy first on 4.18, and the hops to 4.20 and 4.22 need no sync
  • Cost: one reboot of every node when the proxy goes on, one drain when the mirror is removed

Needs: security's approval of the change, on the threat model. One condition: applications cannot use the proxy by default

Ansible does the conversion; the runbook documents and teaches it. The playbooks order the work so that nothing touches the nodes until the proxy phase, which gets its own window, and the mirror comes out only after one connected update has worked. Verification includes proving application pods cannot use the proxy. Ansible runs the retrofit and the hops that follow, as it runs the mirroring today; enabled on 4.18 first, the proxy lets the hops to 4.20 and 4.22 run with no sync at all. The platform owner decides on this approach and takes the change to security on the threat model; the one condition is that applications cannot use the proxy by default.
