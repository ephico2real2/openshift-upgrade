Step 2 · proposed, preferred

Clusters reach Red Hat through the proxy

  • Each cluster's Proxy setting sends platform traffic to the enterprise proxy, which allows only Red Hat's documented hosts
  • Application pods are blocked from the proxy; an image allowlist stops arbitrary pulls
  • No mirror, no sync, no local Update Service, no two-headed DNS
  • Cost: one reboot of every node when the proxy goes on, one drain when the mirror is removed

Needs: security's approval of the change, on the threat model. One condition: applications cannot use the proxy by default

docs/enterprise-proxy/ · runbook not run on any cluster yet · 6

The runbook orders the work so that nothing touches the nodes until the proxy phase, which gets its own window, and the mirror comes out only after one connected update has worked. Verification includes proving application pods cannot use the proxy. The platform owner decides on this approach and takes the change to security on the threat model; the one condition is that applications cannot use the proxy by default.
