We are not after two-headed DNS; we are after a sustainable way to update as we grow. The disconnected setup came from OpenShift 3.x, where the proxy setup was a mess. On 4.x the proxy is Red Hat's way for enterprise customers to take fixes as they ship, and it keeps us ready for the growth that follows (OpenShift 5.x, for example).

The cluster-wide proxy is Red Hat's standard configuration for environments that deny direct internet access. It can be set in install-config.yaml for a new cluster, or on the Proxy object of a running one, which is what the retrofit runbook does. The disconnected setup we run was carried over from OpenShift 3.x, where it was the sound choice because the proxy setup was a mess. OpenShift 4.x is far more advanced, and we have to be ready for the growth that follows it, OpenShift 5.x for example: the cluster-wide proxy is Red Hat's documented, supported way for enterprise customers to take updates and fixes as they ship, which is what operations and vulnerability management need. We are not looking for two-headed DNS; we are looking for a sustainable way to update our clusters that keeps pace with our growth.
