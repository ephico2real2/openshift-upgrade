This is how Step 2 is done: Ansible, as the mirroring is today. The runbook documents and teaches the same phases. Walk the left column top to bottom: the retrofit playbook in three runs, the verify playbook, the first connected update with the mirror still in place as the safety net, the mirror removal, then verification again. Every later hop to 4.20 and 4.22 is the update playbook alone. The red boxes are the gates: an unhealthy cluster stops the run before anything changes, a release whose signature the CVO could not verify stops the next hop, and a workload pod that receives a proxy variable fails verification, which is the one condition security set. The playbooks are tested offline against a stand-in cluster; the first real run is the lab cluster.
