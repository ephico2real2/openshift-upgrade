Our guarantee: the platform proxy never reaches application pods [R1]. Teams may already set a proxy in their own deployments; that is their deliberate choice under existing policy, not a gap we introduce.

This is the one condition of the change the platform owner takes to security on the threat model: applications cannot use the proxy by default. Answer for security: no namespace gets internet access from the Proxy setting. Application pods receive no proxy variables from the platform. An application team that sets HTTPS_PROXY in its own deployment does so deliberately, as it is allowed to today; the platform never sets it for them. The two places a platform component touches app namespaces are in the table, and the Verify playbook checks them: test 6 (no proxy injected), 8 and 9.
