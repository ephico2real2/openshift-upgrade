Today's process, run by Ansible

A bastion in each datacenter downloads Red Hat content once, then pushes that same copy into the lab registry and, after testing, into production.

What it doesn't change: we still mirror everything ourselves, and a person starts each run.

  • Two playbooks: releases, and operator catalogs per version
  • Red Hat pull secret and registry logins in Ansible Vault
  • Persistent cache: later runs fetch only what changed
  • One archive for lab and production: same content
  • Local Update Service: the same upgrade paths as a connected cluster
  • Release signatures kept, as 4.21 and later require

oc-mirror-ansible/ in the repository · tested with stand-ins, not yet against our registries · 6

The playbooks run oc-mirror v2 in two halves: download to disk with a cache that lasts the whole 4.18 to 4.22 road, then push the archive into one registry at a time. The registry namespace is one parameter, ocp4v2, the same on every registry.
