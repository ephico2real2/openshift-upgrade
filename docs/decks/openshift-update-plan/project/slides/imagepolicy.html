Which images may run: two layers

Node · every pull

allowedRegistries

  • CRI-O checks every pull: pods, builds, static pods
  • Must list everything the platform needs
  • Red Hat supported; the backstop

Admission · application namespaces

Kyverno allowed registries

  • Kyverno's standard policy; the list is a ConfigMap in the cluster
  • Stricter for apps: no release repository, no public quay.io
  • Audit first, then deny; per-team exceptions
  • Clear error at oc apply, not ErrImagePull later

Kyverno adds to allowedRegistries, it doesn't replace it: admission never sees a build's FROM image, a static pod or a pull run on a node.

allowedRegistries is enforced by CRI-O on every node and applies "when accessing images for builds and pods". It has to include everything the platform pulls, including quay.io/openshift-release-dev. Restricting images to approved registries is a standard Kyverno use case; we use the library's advanced-restrict-image-registries pattern, with the allowed list in ConfigMap kyverno/allowed-image-registries, so adding a registry is a one-line change. It runs at admission for application namespaces only, so it can be stricter. Tested offline with the Kyverno CLI 1.19.1, 12 of 12 cases. Kyverno is not shipped by Red Hat; its images must be mirrored, and it must run highly available. The same rule can run as a built-in ValidatingAdmissionPolicy instead.
