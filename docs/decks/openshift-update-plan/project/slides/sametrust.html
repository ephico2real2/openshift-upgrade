When Red Hat fixes a bug or a vulnerability, a synced cluster waits for a mirror run. A proxied cluster can take the fix in the next change window, after the lab. We keep the control; we lose the wait.

[R5] update-process-workflow.adoc: "image SHA digests as unique and immutable release image identifiers" · 16

We already trust Red Hat's content: we copy it and run it today. Red Hat signs statements about each release image by its digest, and the cluster's update operator checks them with built-in public keys before it updates; from 4.21 CRI-O also checks Sigstore signatures. That is identical whether the image came through a mirror or the proxy. Syncing only adds a copy step and a delay.
