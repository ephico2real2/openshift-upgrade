Step 3 · proposed, alternative

Red Hat Quay on-prem, filled on a schedule

  • A highly available Quay per datacenter replaces the production mirror registries
  • Quay cannot sync OpenShift content from Red Hat by itself; a timer on each bastion runs the Step 1 playbooks
  • Clusters keep no egress; a local Update Service is required

Needs: a Quay subscription, a platform for it, and a build partner

docs/quay-onprem/ · designed, not built · 19

Red Hat discourages using one single-host mirror registry for several clusters and asks for highly available mirror registries. If each production registry serves several clusters, this step is the long-term answer even if Step 2 is approved.
